# Model-efficiency decision memo

**Status, 2026-11-12:** No quality-preserving compression breakthrough is established. This memo concerns general local inference and benign multistep quality. The [master evidence](master-feasibility-evidence.md), [CPU runtime audit](frontier-cpu-runtime-research-2026-11-12.md), [architecture audit](frontier-architecture-research-2026-11-12.md), and [raw pilot protocol](output-head-cpu-pilot-2026-11-12.md) contain the detailed evidence.

## A claim that could be falsified

For one fully specified checkpoint, tokenizer, runtime, CPU host, and task distribution, compare a deployed candidate with a **same-source Q4_K_M** reference. Predeclare four gates:

1. Complete installed bytes, including model file, decoder or adapter, indexes, tokenizer, and required runtime additions.
2. High-water process RSS and cgroup memory during a cold and a warm request, with page-cache ownership audited.
3. Full-request CPU-seconds, including prefill, generation, verification, retries, and any decompression or routing.
4. Paired, held-out benign multistep task success with an absolute reference floor and a predeclared noninferiority margin.

All four gates must apply to the same loadable artifact and request mix. Decode tokens per second, nominal bits per weight, compressed archive size, and short-form benchmark means cannot substitute for them. A frontier-hosted-model equivalence claim would need a separate, reproducible cross-model evaluation; the current 1.5B experiment does not test it.

## What the local result actually establishes

The output-head-only file is 60,166,656 bytes (5.38%) smaller than the freshly built same-source Q4_K_M GGUF, and the [tensor audit](../data/output-head-q4-pinned-map-2026-11-12.json) found all 338 other tensor payloads byte identical. Five paired warm 512/128 synthetic no-repack runs and five admitted cold cgroup no-repack pairs favored the candidate on child CPU time and peak memory. Five paired warm **default-repack** runs also favored it on child CPU and process RSS, with a median RSS advantage of 11,456,512 bytes. However, the [accepted default-repack cold cgroup repeat](../data/frontier-cpu-head-cold-cgroup-default-repack-2026-11-12.json) found candidate `memory.peak` **higher in all five pairs**, by a median 73,035,776 bytes, while child CPU was lower by a median 1.697 seconds and process RSS was lower by a median 13,266,944 bytes. An [independent 100 ms memory trace](../data/frontier-cpu-head-cold-cgroup-default-repack-memory-trace-2026-11-12.json) repeated the cgroup reversal in five accepted pairs. At the sampled near-peaks, candidate-minus-reference anonymous charge was +131,256,320 to +133,345,280 bytes while file charge was -60,166,144 bytes. The changed candidate head's quantized payload is 131,272,704 bytes, so one additional anonymous copy of approximately that size is consistent with the net memory increase. The trace does not directly identify a per-tensor allocation. Thus the candidate fails the full-memory gate under the pinned default runtime path. These are one-host, one-request-shape synthetic observations; full-service task accounting remains open.

The 1.5B Q4_K_M reference failed the [development quality screen](generated-multistep-quality-protocol-2026-11-12.md): on the best 512-token prompt, it solved 5/8 generated arithmetic and 3/8 ordered-state cases. No evaluation manifest was frozen and no candidate quality result has passed a held-out gate. The current resource lead therefore says nothing about retained capability. [Muse Glimmer](https://arxiv.org/html/2610.24628v3) and [llama.cpp's output-tensor-type option](https://github.com/ggml-org/llama.cpp) also make selective output-head quantization prior art. Our measurement is a deployment observation, not a new algorithm.

A narrower [Q5_K output-head control](../data/frontier-cpu-head-q5-cold-cgroup-default-repack-retry-2026-11-12.json) changes only `output.weight` from Q6_K to Q5_K. Four admitted counterbalanced cold default-repack pairs favor it over the reference on cgroup peak (median -32,163,840 bytes), process RSS (-32,710,656 bytes), and benchmark-child CPU (-1.420 seconds). Its GGUF is 30,994,944 bytes smaller than the reference but 14,740,992 bytes larger than a same-source whole-format Q4_K_S control. The predeclared five-pair resource confirmation is incomplete because the fifth reference run failed reclaim admission twice. Installed bundle, complete-task CPU, and sealed quality have not been measured. This is a lead to test, not a four-gate result.

## Ranked experiments

| Rank | Hypothesis and smallest decisive test | Reject when |
| --- | --- | --- |
| 1 | **Selective output-head precision with explicit runtime mode.** The current candidate already fails default-repack cgroup memory. Test an explicit no-repack deployment only if that runtime mode is acceptable, on a stronger reference that clears a development floor. Measure token-class-sensitive logits and complete B/R/C, then run a sealed paired task set with dependent steps. Add a simple Q4_K_S whole-format control. | The no-repack deployed candidate loses a resource gate or the sealed quality gate, including rare-token or dependent-step strata. A favorable 16-item development screen alone is insufficient. |
| 2 | **Physical width reduction aligned to quantizer blocks.** Build trim-only, trim-plus-recovery, and unpruned equal-recovery-budget controls from one source. Audit tensor shapes and exact GGUF bytes before CPU testing. [UniQL](https://arxiv.org/html/2512.03383) and [the Qwen3.5 pruning report](https://arxiv.org/html/2608.15693) illustrate why lower parameter count and better CPU deployment cannot be inferred from each other. | Tensor dimensions do not shrink, block padding erases file savings, recovery cost dominates, or held-out quality falls. |
| 3 | **Block-addressable weight coding fused into CPU matrix kernels.** Prototype one large Q4_K tensor group against the native CPU kernel; measure actual bytes read, decode CPU, scratch and resident duplicates before building a full model. The [local byte audit](../data/frontier-cpu-runtime-entropy-2026-11-12.json) found only a 2.2571% `zstd -3 -T1` whole-file reduction on a pinned Q4_K_M artifact; [MINE](https://arxiv.org/html/2611.09424v2) and [ZipServ](https://arxiv.org/html/2603.17435) are GPU results on different model formats. | Fused execution does not lower full-request CPU-seconds, complete bytes, and high-water memory after decoder/index overhead. |

These are experiments to test, not predicted winners. Independent-question batching from [Li et al.](https://arxiv.org/html/2610.27190) is a separate scheduling idea: the reported token savings do not establish that dependent steps can be combined correctly or that a small CPU deployment meets the four gates.

## Quality design before another large run

The next benchmark should separately score isolated primitives, multiple independent questions in one prompt, and a dependent chain built from those primitives. Hold out task **structures** as well as numeric instances. Record downstream errors conditional on correct isolated primitives, normal stops, format compliance, generated tokens, retries, and full CPU cost. Choose the scoring rule before candidate responses. This design can show where integration fails without attributing every failure to compression.

Sample size needs an independent pilot of paired discordance. Under a clearly hypothetical equal-80%-success, 10%-discordance scenario, the [locked-gate simulation](../data/paired-quality-sample-planning-2026-11-12.json) passes only 1.87% of 10,000 two-family trials at 300 cases per family, and 91.31% at 1,200. The simulation assumes independent items and symmetric errors; it is not an estimate for the current models. A 1,200-per-family two-arm test entails 4,800 responses, so the evaluation budget and frozen design should be decided together. The present four-template generator is too narrow for a broad generalization claim.

The unit of inference must be specified before increasing that count. Repeating numeric instances of four story templates can make item-level intervals look precise while leaving uncertainty about new task structures unresolved. [Miller et al.](https://www.anthropic.com/research/statistical-approach-to-model-evals) show why related evaluation questions require clustering at the shared source; [NIST's evaluation practice draft](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.800-2.ipd.pdf) likewise calls for uncertainty to match the target population and the sources of variation. The current exact binomial gate is valid only under its independent-item sampling model and cannot support a structural-generalization claim from four templates. The next freeze should name the sampled unit, include many independent structures, and stratify by dependency depth and task family. Report the paired item outcomes and a prespecified structure-aware analysis. Treat any conditional downstream score as diagnostic unless its denominator and multiplicity rule were frozen in advance.

For scale, 1,200 cases drawn equally from four templates means 300 repetitions per template. Under the illustrative equal-cluster design-effect formula `1 + (m - 1)rho`, an intra-template outcome correlation of 0.05 gives an effective item count near 75 rather than 1,200. This is a sensitivity calculation, not a measured correlation or a valid confidence interval for four clusters. More independent structures, rather than repeated numbers in the same four structures, are the first requirement for a broad claim.

There is also a measurable cost to the chosen conservative interval. [Tango's paired-proportion work](https://pubmed.ncbi.nlm.nih.gov/9595618/) derives a one-sided score test and interval for paired binary outcomes; the current protocol instead subtracts separately bounded discordance probabilities and allocates alpha across six assertions. A more efficient paired noninferiority procedure is worth a prospective coverage and power audit, including boundary cases and multiplicity, before replacing the locked rule. Lowering the margin or switching intervals after observing candidate outcomes would invalidate the confirmatory interpretation.
