# Runtime AI evidence follow-up: code generation, decisions, and field use

Reviewed 2026-11-09; publication wording revised 2026-11-27. This note adds four original investigations to the [runtime-AI audit](runtime-ai-evidence-audit.md). It tests whether a reported model result changed an already running program's code, changed a decision within fixed code, or only influenced development before deployment. The [Project Drexel feasibility assessment](drexel-feasibility-assessment.md) defines the repeated-adaptation research benchmark.

| Investigation | Directly reported evidence | Research judgment and limit |
| --- | --- | --- |
| **MalTerminal** | [SentinelLABS](https://www.sentinelone.com/labs/prompts-as-code-embedded-keys-the-hunt-for-llm-enabled-malware/) examined Python scripts and a Windows executable designed to request malicious code from GPT-4 at runtime. Related scripts ask an operator to choose the kind of code to generate. The investigators found no evidence of deployment, sale, or distribution. | This is a runtime **code-generation design**, but the report does not demonstrate a deployed remote access program rewriting its own payload, retaining function, and revising it again. The deprecated API endpoint suggests an early sample; it does not prove its build date. |
| **AI-gated dropper** | [Unit 42](https://unit42.paloaltonetworks.com/ai-use-in-malware/) analyzed a sample that submits host context to a remote GPT-4 service and uses the returned decision to decide whether to proceed. The article's two cases came from open-source intelligence hunts, not incident telemetry. | The model controls a **decision gate** within pre-existing code. Unit 42 does not report model-written payload revisions or verified deployment of this sample. Its example log illustrates the response path but does not establish an infection in the field. |
| **.NET infostealer with LLM calls** | In the same [Unit 42 analysis](https://unit42.paloaltonetworks.com/ai-use-in-malware/), three related samples call GPT-3.5-Turbo. Investigators found that the calls did not improve the stealer's behavior; one generated technique name was only logged, and other advertised AI functions were ineffective. | The report calls this “AI theater.” An API call or AI-themed log entry is not evidence of adaptation. These samples also came from the authors' open-source intelligence hunt. |
| **CL-UNK-1211 espionage campaign** | [Unit 42](https://unit42.paloaltonetworks.com/ai-campaign-targets-linux-infrastructure/) observed an October 2025–April 2026 campaign with deployed scripts containing conversational comments and reasoning notes consistent with AI-generated code or automated agent deployment. It separately documented a custom remote access trojan, SysGoRAT. | This is **field evidence of suspicious AI-assisted payload preparation**, with authorship inferred from artifacts. The report does not tie the RAT to a runtime model call or show it revising its own code. The investigators do not attribute the cluster to a named state or criminal actor. |

## A named-actor cross-check

[Check Point Research's KONNI investigation](https://research.checkpoint.com/2026/konni-targets-developers-with-ai-malware/) reports a phishing campaign with a PowerShell backdoor and assesses that instructional comments and code structure strongly suggest AI-assisted development. The AI assessment is an **inference from script artifacts**, not a recovered development transcript. The report describes fixed backdoor logic and operator tasking, not a model integrated into the running backdoor. A named APT and an AI-generated backdoor therefore do not, by themselves, establish AI-modified malware in the *Drexel* sense.

## Updated evidence boundary

These cases fill three different cells: runtime generation in an unconfirmed sample (MalTerminal), runtime choice among fixed behavior in an unconfirmed sample (the Unit 42 dropper), and probable AI assistance during preparation of payloads used in intrusions (CL-UNK-1211 and KONNI). None supplies an incident-linked sequence of **model response → applied revision of the same deployed program → retained remote access function → another revision**. [Mandiant's separate field claim](local-model-claim-audit.md) reports runtime changes to command strings, but likewise omits a public artifact chain. This conclusion is limited to the reports reviewed here; it is not a claim that no such system exists.
