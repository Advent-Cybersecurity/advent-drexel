# Project Drexel: where a reported revision occurs

Jashid Sany, Advent Cybersecurity. 27 November 2026 (America/New_York). This source-only continuation re-extracts five cases from the prior [31-case ledger](../data/closest-case-claim-ledger-2026-11-26.json). It is a purposive comparison, not a census, independent reproduction, or estimate of prevalence. No model, malware, endpoint product, or candidate code was run. The [companion data](../data/revision-placement-case-extraction-2026-11-27.json) records eight fields per case, with source locators and explicit unknowns.

## Why placement changes the claim

The expanded Project Drexel subclaim joins two model-caused active code revisions in **one continuing remote-access process** to an independent remote task result after **each**. A model may instead act in the operator's build environment; a test controller may launch each candidate on a restored endpoint; a resident program may adjust a parameter rather than executable code; or a benign agent may change its own logic without any remote-access task. These are distinct units of analysis. Combining results from them cannot substitute for one joined revision chain.

| Primary case | Established contribution | Boundary for the strict claim |
| --- | --- | --- |
| [LLMalMorph, v2](https://arxiv.org/html/2507.09411v2) | The authors report 618 compiled variants from ten source projects. [Algorithm 2](https://arxiv.org/html/2507.09411v2) carries earlier function edits into later variants; human debugging resolves compilation failures. | This is cumulative **offline** source evolution. The published function-preservation and detection measures do not show a resident instance adopting versions or retaining remote access after each. Human corrections also limit a fully autonomous authorship claim. |
| [Yuan et al., v1](https://arxiv.org/html/2608.01639v1) | A controller generates and tests candidates against endpoint products; its baseline check considers C2 function, and the reported evasion criterion includes a stable connection and heartbeat over 30 seconds. | The [evaluation method](https://arxiv.org/html/2608.01639v1) restores a clean VM snapshot after each test. Candidate refinement is not revision of one continuing endpoint process. Product-specific outcomes and heuristic alert-cause labels do not establish universal invisibility. |
| [Gödel Agent, paper](https://arxiv.org/html/2410.04444) and [pinned implementation](https://github.com/Arvid-pku/Godel_Agent/blob/bbb508796be31c7140cdfc7106efd830a1324242/src/agent_module.py) | The authors report repeated model-guided self-optimization on benign reasoning tasks; the code supports function and method replacement in the interpreter. | The public material does not provide a model-output-to-version-to-PID-to-result trace across two selected changes. Its task outcomes are not remote-access results, and its robustness figures cannot be applied to an implant. |
| [Rigaki and Garcia](https://www.stratosphereips.org/s/Bringing_a_GAN_to_a_Knife_fight_submission_draft.pdf) | A laboratory RAT maintained a C2 channel while a separate GAN adjusted traffic timing and sizes under one configured network detector. | The live changes were **parameters**, not new executable payload code. The paper's detector result is confined to its selected traffic profile, IPS configuration, and lab setting; it does not show after-each-version remote command results or general defender invisibility. |
| [Anthropic GTG-20006](https://www.anthropic.com/threat-intelligence-report-september-2026) | Anthropic reports an actor-side AI workflow that monitored detections, modified and rebuilt artifacts, and staged them for redeployment in operations. | Rebuilt and redelivered artifacts are not two revisions accepted by the original resident process. The described intent to iterate until undetected is not a published per-version endpoint alert series or remote task result. |

The sources provide useful **component evidence**. LLMalMorph establishes cumulative model-influenced source changes; Yuan et al. show candidate-level endpoint function and product tests; Gödel Agent is a benign in-interpreter revision precedent; Rigaki and Garcia show live parameter adaptation with continuing C2 traffic; Anthropic shows operator-side development linked to field activity. None of these five sources supplies all strict links in one unit of analysis. That conclusion is limited to the inspected public records, not a claim that the system is impossible.

## Implications for the next analysis

For each future case, the extraction must ask **where the model runs, which object changes, what instance executes it, and which result is checked**. A detection score from uploaded binaries is not an endpoint session outcome. A heartbeat after a fresh launch is not retained function after a resident update. A live traffic-parameter change is not executable-code revision. A service or actor remaining active across new builds is not process continuity. These distinctions should appear in the next paper version before any pooled claim about feasibility or visibility.
