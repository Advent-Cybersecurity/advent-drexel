# Cairn field case: generated shell versus resident revision

Advent Cybersecurity source audit, 26 November 2026. This note reads [Amazon Threat Intelligence's 20 November first-party incident report](https://aws.amazon.com/blogs/security/chinese-nexus-actors-cairn-ai-agents-found-a-zero-day-on-their-own/) as evidence for the Drexel feasibility question. No model, agent, payload, or sample was run.

Amazon says its investigators found an unauthenticated Cairn controller and could inspect project configuration, operator prompts, and AI output from a roughly 48-hour campaign against university networks. The human supplied targets and variations of the goal “obtain shell access”; Amazon reports that agents then planned and adjusted their actions. These are stronger causal observations than an AI-style code comment, but the article does not publish an exact model response-to-payload artifact, hash, or full transcript for the shell step. Model-to-payload causation is therefore **first-party reported**, not independently reconstructable from the article.

The most relevant sequence is one target running a medical-imaging application. Amazon reports that agents identified a vulnerable upload filename parameter and gained arbitrary file write about 11 minutes after mapping the API. **In a later session**, they used the same flaw to write a Python reverse-shell payload to `sitecustomize.py` and called a training API endpoint. That endpoint **spawned a new Python process**; the new interpreter imported the file and established a root shell. This is a functional remote-access outcome for one externally written payload. The code became active at interpreter startup in a new process, so the observation does not establish in-place revision of the original application, continuity of one implant process, two accepted versions, or a separate remote task/result after each version.

The wider campaign is a warning against treating “agent kept trying” as a success rate for this mechanism. Amazon separately reports a 16-hour, 148-action Redis attempt and more than 30,000 credential combinations across other targets without a working login. Those are different objectives, target systems, and outcome units, not failed trials of serial live-payload revision. Amazon also says a person later supplied a proxy to a second network and **infers** that the same zero-day had been used to establish it; that inference is not a second witnessed shell-payload version.

This case narrows the paper's wording: a model-directed agent can reportedly cause a new remote shell payload to run during a real intrusion, while the specific startup path demonstrates **new-process execution**. A later claim of resident, repeated self-revision needs version-bound process lineage and after-each command evidence that Amazon's public account does not contain.
