# PROMPTFLUX: public evidence case file

Reviewed 2026-11-09. This case file collects the public record about PROMPTFLUX for adversary-behavior research. It separates facts reported from sample analysis, file metadata, later summaries, and unverified claims. No malware sample was downloaded or run for this study.

## Finding in brief

PROMPTFLUX is an **unattributed, experimental Windows VBScript dropper** that Google Threat Intelligence Group (GTIG) identified in early June 2025. Its distinguishing idea was to ask a hosted Gemini model for rewritten script code during execution. GTIG examined multiple variations, including a “Thinking Robot” module that logged model responses and a “Thinging” variant that requested a full rewrite every hour. The self-update function was commented out in the sample GTIG discussed in detail. GTIG said the family was in development or testing, lacked demonstrated ability to compromise a victim device or network, and was not then used in the wild. [GTIG original report, November 5, 2025](https://cloud.google.com/blog/topics/threat-intelligence/threat-actor-usage-of-ai-tools).

The public record establishes **an attempted model-assisted self-rewrite design**. It does not establish a repeated sequence of successful model output, applied code changes, retained function, and field deployment.

## Cross-source audit

**GTIG's summary is broader than its demonstrated result.** Its overview table describes regenerated code saved to Startup and attempted spread. Its detailed text says the examined self-update function was commented out, other features were incomplete, and the family could not then compromise a device or network. The latter statements set the evidence ceiling for a functioning infection. [GTIG](https://cloud.google.com/blog/topics/threat-intelligence/threat-actor-usage-of-ai-tools).

**CAIRN adds metadata, while its behavioral conclusion needs a separate proof.** Cisco Talos's [CAIRN project](https://github.com/Cisco-Talos/Cognitive-Artifact-Intelligence-Research-Network) explicitly works from VirusTotal metadata, without downloading or detonating binaries. Its [PROMPTFLUX entry](https://github.com/Cisco-Talos/Cognitive-Artifact-Intelligence-Research-Network/blob/main/docs/families/PROMPTFLUX.md) describes a dropped PE that successfully overwrites itself with Gemini output and treats many unseen mutations as likely. The same entry lists rewrite fidelity as an open question. It supplies no paired before-and-after payloads, runtime trace, or victim incident demonstrating that asserted loop. Its PE-centered architecture also differs from GTIG's description of a VBScript self-rewrite. This review therefore uses CAIRN for its explicitly reported file metadata and records the self-overwrite claim as **unverified**.

**Other later mentions are not independent execution evidence.** [ESET's H2 2025 threat report](https://web-assets.esetstatic.com/wls/en/papers/threat-reports/eset-threat-report-h22025.pdf) explicitly attributes its PROMPTFLUX description to GTIG and calls the family experimental. [Splunk's PromptFlux analytics story](https://research.splunk.com/stories/promptflux/) cites GTIG as its only reference and offers detection content; its references to command execution, process injection, or C2 should not be treated as independently observed PROMPTFLUX behavior. [M-Trends 2026](https://cloud.google.com/blog/topics/threat-intelligence/m-trends-2026) and [GTIG's May 2026 report](https://cloud.google.com/blog/topics/threat-intelligence/ai-vulnerability-exploitation-initial-access) come from the original research organization and do not supply a new sample-level validation trace.

**A later secondary account converts intended behavior into an asserted result.** A [Cloud Security Alliance 2026 rapid-research report](https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/05/adversarial-ai-native-threat-actors-systemic-risk-v1-csa-styled.pdf) says PROMPTFLUX rewrites its entire source hourly and treats successor signatures as already deployed. It cites [GTIG's original investigation](https://cloud.google.com/blog/topics/threat-intelligence/threat-actor-usage-of-ai-tools), which instead says the examined self-update function was commented out, the family was experimental, and it had no demonstrated ability to compromise a device. GTIG does describe a variant *prompting* for hourly full-source rewrites, but publishes no matched model response, applied revised script, or functional successor. The stronger secondary assertion should not be counted as an independent observation. This is a concrete example of how an architectural intention becomes an apparently operational fact when a case is retold.

**The family description also drifts within the original publisher's reports.** [AhnLab's AI-tool overview](https://www.ahnlab.com/en/contents/content-center/36185) calls PROMPTFLUX a periodically self-rewriting dropper and HONESTCUE a just-in-time self-modifier that requests VBScript obfuscation. [GTIG's May 2026 overview](https://cloud.google.com/blog/topics/threat-intelligence/ai-vulnerability-exploitation-initial-access) also assigns the VBScript self-modification wording to HONESTCUE, even though its own table labels HONESTCUE “Evasion Payload Generation.” GTIG's more detailed [February HONESTCUE investigation](https://cloud.google.com/blog/topics/threat-intelligence/distillation-experimentation-integration-ai-adversarial-use) identifies it as a framework that requests **C# second-stage downloader/launcher code**, compiles it in memory, and explicitly says it does not use an LLM to update itself. GTIG's original PROMPTFLUX account reports an experimental rewrite design, not a verified applied rewrite. The later summaries do not supply new sample-level evidence to resolve those conflicts; the detailed technical observations set the narrower evidentiary ceiling.

**IOC collections need family-level checking.** One [combined PROMPTFLUX/PROMPTSTEAL IOC page](https://intel.threadlinqs.com/threat/TL-2026-1508) prints a hash containing `...cf2048a1...`; GTIG's direct [file link](https://www.virustotal.com/gui/file/eb0687daed29f3651c61b0a2aa4a0cdcf2049a1ebae2e15e2dd9326471d318a1) contains `...cf2049a1...`. The list also mixes hashes from several families. This case file uses the GTIG-linked value and does not assign the other combined-list hashes to PROMPTFLUX.

An [independent public analyst comment](https://bsky.app/profile/doublepulsar.com/post/3m4vgdgj7mc2d) says historical telemetry showed broad static antivirus detection and that PROMPTFLUX was only testing. The post does not publish the telemetry or a sample-to-host trace, so it is useful context rather than a quantified prevalence or damage finding.

## Open questions that would change the assessment

1. Which published hash belongs to each named variant, and are there exact-hash independent analyses of both?
2. Did any sample receive a usable model response, apply it, and run the resulting script successfully? The public sources do not show a matched request, response, and new artifact.
3. Did a revised copy preserve behavior across several generations, or did code quality drift break the loop?
4. Was any copy delivered to a real victim, persisted after reboot, or successfully copied to another host or removable drive?
5. Did any later variant use local host or detection feedback to decide what to change, rather than asking on a fixed schedule?
6. Is there a verified relationship between the linked file, the decoy installer, and CAIRN's claimed PE payload?
7. Has any investigator tied PROMPTFLUX to a named actor, campaign, victim sector, or geography with evidence stronger than a lure filename?

As of this review, PROMPTFLUX remains the closest **reported design** to the expanded self-rewriting hypothesis in this repository. The published evidence still stops before a confirmed working, repeated, deployed self-update loop.
