# Cross-actor decision patterns for red teams

Reviewed 2026-11-09. This source-based brief compares **nine reported activity clusters**. It asks where each group placed flexibility: campaign delivery, a target-specific build, a maintained tool portfolio, the developer workflow, or a running program. The "red-team reading" is our reconstruction of decision pressure. It is not an actor statement or a claim that every member of a group shared one strategy.

## Where each group changed course

**Campaign, build, and runtime changes appear in different reports.** APT29 and UAC-0099 changed campaign or build artifacts; Sandworm used a target-specific build. APT41, TEMP.Zagros, and APT27 used a model during development or infrastructure work. APT28 is the operational case here with model-generated commands inside a running malware workflow. APT36 and SilkParasite maintained different tool portfolios, with different strengths of evidence for AI assistance.

**APT36 and SilkParasite show different portfolios.** Bitdefender's APT36 investigation found many variants and some incomplete logic. Its SilkParasite investigation found a maintained modular portfolio and only circumstantial AI-development clues. The reports do not establish a general quality ranking for all actors or a causal relationship between AI use and defects.

**Runtime self-rewriting remains unverified.** A downloader that changes across releases, a configurable industrial payload, and a runtime model call each offer flexibility at a different point. The cited sources support those points of flexibility, without showing a deployed program that repeatedly rewrites its own code.

## Questions to carry into an authorized emulation brief

1. What mission-level outcome would remain fixed across changes in the target environment?
2. Which layer would the actor likely revise: delivery, build, supporting infrastructure, operator workflow, or runtime action selection?
3. Which observation would support that choice, and which part is only an inference about motive or organization?
4. Does AI appear in development, in a running program, or only as a researcher's inference from artifacts?
5. What failure or quality cost appears alongside the reported flexibility?
