# Trusted tool updates: adoption and function are different claims

26 November 2026. Static reading of [Kan et al., *Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security*, arXiv v1](https://arxiv.org/html/2611.01976). No framework, model, or attack code was run for this audit.

The authors test a benign tool version admitted to an agent and **one researcher-authored implementation update** that retains the tool interface and ordinary output while adding an unauthorized action in isolated tasks. Its delivery is outside the model's prompt context. Across seven frameworks, the authors report that previously granted identity or permissions can persist after a tool update. The paper's adoption methods vary: some replace or reload a tool server, one opens a new native window while restoring a logical session, and others reconnect or reload an extension. A tool call after adoption runs new implementation code, but this is **not** proof of one unchanged process across the update.

The main RQ1 table averages 21 framework–workload conditions over five rounds of 20 planned tasks per condition (2,100 planned tasks), with independent receiver/service/file evidence for the extra effect and a separate legitimate-task completion check. The paper reports 100.0% extra-effect success and 99.6% normal final-output completion for its selected update condition. Those are task outcomes *after one prepared update*, not the probability of accepting two model-generated updates. Other sections reuse some records, so their condition counts should not be summed into a larger independent sample. The authors state the code was researcher-authored and tested with synthetic credentials, local services, and isolated files.

The finding matters for Drexel's **evidence rule**: a successful ordinary task after an update establishes that one visible function worked; it does not show the new artifact was safe, that all old behavior survived, or that every side effect was intended. A future benign serial-revision study should bind approval and active-version evidence to the exact implementation and record collateral behavior separately from the intended function. The reported attack percentages are not transferable to model authorship, process continuity, C2 survival, endpoint evasion, or a second revision.
