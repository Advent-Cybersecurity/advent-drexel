# Hyperspace source audit: agent code evolution versus a resident revised instance

26 November 2026, Advent Cybersecurity. Read-only review at repository commit [`9b53c901b6044b4d3aa0b74703081d15648fb591`](https://github.com/opinionated-systems/hyperspace/tree/9b53c901b6044b4d3aa0b74703081d15648fb591). No code, model, or benchmark was run. Repository documentation and static implementation are primary for the architecture; the reported counts are author claims, not independently replicated here.

## Why it is relevant

The authors report agents editing their own Python harness code over many generations and voluntarily adopting another agent's code. Their [top-level report](https://github.com/opinionated-systems/hyperspace/blob/9b53c901b6044b4d3aa0b74703081d15648fb591/README.md) says 20 paired runs across five model pairings yielded 30 detected adoption events, and reports substantial score swings between generations. Published per-generation source snapshots, metadata, and model-call JSONL files make this a stronger provenance lead than a bare “self-improving” label. The application is benign IMO-answer grading, not remote control.

## The actual execution boundary

The [replication description](https://github.com/opinionated-systems/hyperspace/blob/9b53c901b6044b4d3aa0b74703081d15648fb591/replication/README.md) says each generation forks a selected parent's source tree, runs a meta agent on the child tree, evaluates the modified task agent, and adds a candidate to an archive. This is a branching search, so generation number alone does not identify a cumulative single lineage. The documented result record stores a full source tree per generation and an LLM-call log.

The [generation loop](https://github.com/opinionated-systems/hyperspace/blob/9b53c901b6044b4d3aa0b74703081d15648fb591/replication/generate_loop.py) clears cached `agent` modules, loads a meta-agent class from a selected source path with `importlib`, instantiates it, and invokes it against the copied child repository. It then evaluates `task_agent.py` on train and validation tasks. At the end, it picks the archive member with the highest saved validation score for a separate test run. The [evaluation harness](https://github.com/opinionated-systems/hyperspace/blob/9b53c901b6044b4d3aa0b74703081d15648fb591/replication/evaluation/harness.py) likewise clears cached modules, loads the candidate `TaskAgent` class, and instantiates a **new object for each dataset row**. The outer Python process can be reused across generations, and changed code can be imported into it, but the task agent serving one case is not the same object continuing through successive code changes. No stable process-ID/start-time trace was inspected in the released results.

The [transfer protocol](https://github.com/opinionated-systems/hyperspace/blob/9b53c901b6044b4d3aa0b74703081d15648fb591/transfer_experiment/README.md) alternates two agents' generations. Peer source is exposed in a `strategies/` directory; the model can read and copy it, and the modified candidate is scored before a strategy is published. This supports the authors' claim that model-guided code *adoption* is a meaningful event in the search, but not a claim that two accepted changes became active in one remote-access instance. The authors' document also records a prior attractive edit to `llm_client.py` that broke evaluation, illustrating the difference between a plausible patch and a functioning candidate.

## Bounded conclusion for Drexel

This case establishes an author-reported, artifact-rich **model-to-candidate-code** search and a static path for loading changed Python code during one outer evaluator run. It does not supply the exact Drexel chain: one identified resident payload object or process adopting two model-caused code revisions in sequence, with an independently issued remote task succeeding after each. A paper should specify whether “same process” means the outer evaluator or the changing service whose function the claim concerns; otherwise it can falsely classify this example as resident self-revision. Its author-reported accuracy, adoption count, and seed variance are specific to IMO grading and cannot serve as malware or access-survival rates.
