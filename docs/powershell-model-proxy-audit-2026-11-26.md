# Smaller-model malware generation: behavior proxy versus live function

26 November 2026. Source-only audit of [Pianese et al., *AI-Generated PowerShell Malware: An Experimental Framework and Dataset*, arXiv v1](https://arxiv.org/html/2606.30819). No model, sample, or sandbox was run here.

The authors curate malicious PowerShell scripts and shorter commands with natural-language descriptions, fine-tune four roughly 7–9B-parameter open-weight model configurations, and compare generated scripts with held-out references. The primary dynamic comparison runs generated and reference scripts in **separate**, restored Windows 10 VM instances. The test set has 236 samples; the reported Sigma-rule overlap analysis conditions on the **212** whose reference script triggered at least one rule. Endpoint security mechanisms are disabled to permit execution, while Sysmon, PowerShell, and Windows event logs feed a selected Sigma rule set. A triggered-rule set is an observable behavior proxy, not proof that a remote-control command was received, executed, and returned.

For the best native-precision model, the paper reports median Jaccard overlap **84.5%** and exact rule-set match **48.4%** in that conditioned cohort. The same model's 4-bit AWQ exact-match figure is **35.9%**. These are per-sample matches to a *reference's selected alert-rule IDs*, not the probability that a complete malicious program works or that it survives an update. The comparison does not test two active versions in one process, a retained C2 channel, or an operational EDR. It also cannot establish detection evasion because endpoint protection was disabled and the Sigma rules were used as **evaluation features**.

The resource framing needs a separate check. The paper describes one quantized arm as a resource-constrained or potentially endpoint-embedded scenario, but says **training and inference in the reported experiments used a 32-core Intel Ice Lake system with four NVIDIA A100 64 GB GPUs** and vLLM 0.17.1. It gives no measured CPU-only endpoint memory, file/dependency budget, full-request latency, or energy for this task. The quantization result therefore demonstrates a changed model representation and task-proxy performance on the stated HPC system, not that a 7–9B model can run an entire Drexel revision loop within a particular endpoint's CPU/RAM budget.

**Feasibility implication:** domain specialization can improve a bounded generation task, but generated-code behavior, a detector-rule match, a working remote-control loop, and serial live revision remain different outcomes. A later paper should report the 212-reference-triggered denominator and the separate quantized result, then reserve any endpoint-resource or two-change claim for measurements on the target hardware and process lineage. The dataset and framework are identified by the authors; they were not downloaded or executed for this review.
