# Generated executable detection: a bounded negative result

26 November 2026. Source-only review for Advent Cybersecurity; no model or sample was run.

[Sugio and Ito, *Jailbreak-Free LLM-Assisted Malware Generation*, IEEE Access 14 (2026), DOI 10.1109/ACCESS.2026.3681295](https://ieeexplore.ieee.org/abstract/document/11475468) investigate the composition of function-oriented model outputs into executable artifacts. The [public author-manuscript text](https://www.researchgate.net/publication/403559116_Jailbreak-Free_LLM-Assisted_Malware_Generation_An_Empirical_and_Conceptual_Analysis) gives the setup and table used here. The manuscript is marked accepted but not fully edited; the publisher record gives 6 April 2026 as publication date.

The study's attacker-side host and Windows 11 VM generate, assemble, functionally check, and package code from ChatGPT-4o or Gemini 1.5 Pro. A separate Windows 11 VM executes the artifact. Each trial starts from a restored snapshot. The measured capability classes are a wiper-like file-integrity action and a keylogger-like confidentiality action; the paper explicitly excludes complex network and persistence mechanisms. Model-directed refinement occurs during **development**, before a fresh packaged artifact is transferred to the target. It is not a running implant that revises its own code.

The authors submit functionally verified executables to Hybrid Analysis under default static and dynamic analysis. Their Table 3 reports “Flagged” in both analysis modes for six model/obfuscation conditions: two baseline model sources and each combined with PyObfuscator or PyArmor. They also report unflagged auxiliary Python source and steganographic image carriers, which reinforces that the artifact type changes the observed result. The text says experiments were repeated but does not expose a clear per-condition sample count in the table; **six conditions are not six independent trials**, and a population detection rate with uncertainty cannot be computed from it. The platform's proprietary detection logic and the fixed packaging pipeline limit causal attribution. The paper says unsigned executable structure may matter but does not isolate it.

This is a direct counterexample to the broad proposition that model-written or simply source-obfuscated code is automatically invisible to security analysis. It does not imply that every endpoint product blocks such code: an analysis-platform flag is different from on-host prevention, the tasks are not a remote-access program, the code is not revised after launch, and no two-version access chain is tested. It also does not directly contradict [COGENT's different endpoint and workflow abstracts](cogent-endpoint-claim-audit-2026-11-26.md). A comparative claim would need the same payload semantics, artifact packaging, product configuration, functional oracle, observation window, and clear trial denominator.
