# Adaptive malware and agentic intrusions: 2026 evidence update

Reviewed 2026-11-09. This note extends the [comparative findings](findings.md) with original investigations published in 2026. It separates controlled experiments, analyzed samples, and observed intrusions. Those are different levels of evidence for autonomous malware.

## What the new reports establish

| Evidence | Source and observed result | Limit for this research question |
| --- | --- | --- |
| Controlled research | [Guan et al., June 2026 preprint](https://arxiv.org/html/2606.03811v1) describe an adaptive, self-propagating agent in an isolated virtual network. Across 15 seven-day runs, the mean was 20.4 hosts with launched replicas; the authors also report occasional self-code changes after failure. | Every target was vulnerable and none had active endpoint protection. Main-run inference came from a shared pool; setting up a new local model service was evaluated separately. This demonstrates a capability under containment, not a threat actor's deployment. The manuscript says it is under peer review and withholds operational details. |
| Analyzed malware sample | [Cisco Talos, September 2026](https://blog.talosintelligence.com/the-closed-quorum-inside-the-first-reported-autonomous-ai-c2-implant/) analyzed CLOSEDQUORUM, whose design delegates bounded next-action choices to several model services. | Talos has no confirmation of deployment. The public build has placeholder credentials; Talos did not observe an end-to-end run. Model-directed action selection also differs from repeated code rewriting. |
| Observed agent activity | [Unit 42, July 2026](https://unit42.paloaltonetworks.com/autonomous-ai-cyber-attack-campaign/) recovered logs from a May 7 attack session in which an agent changed targets after an unsuccessful approach and attempted further attacks. The wider campaign mixed automated attempts with manual exploitation. | This is evidence of an adaptive offensive *workflow*. Unit 42 says the autonomous campaigns did not fully compromise their intended targets. It does not show malware changing its code on a victim host. |
| Live intrusions involving agentic frameworks | [GTIG and Mandiant, October 2026](https://cloud.google.com/blog/topics/threat-intelligence/artex-and-friends-enter-agentic-offensive-frameworks) report multiple frameworks used in incident response cases, with activity across several phases of intrusions. | Framework use in an intrusion does not establish that the framework independently made every decision, or that a deployed implant self-modified. The report does not quantify human oversight across all cases. |
| Vendor telemetry sample | [Unit 42, August 2026](https://unit42.paloaltonetworks.com/ai-enabled-malware-analysis/) examined 405 broadly selected AI-related hashes; 12 appeared on its protected production endpoints and all 12 generated alerts. Its endpoint window was December 2024 through June 2025. | The selection includes AI branding and research samples, so 12/405 is **not** a prevalence estimate for all AI malware. The result is limited to Unit 42's dataset, telemetry coverage, and dates. |

The current evidence supports a narrow distinction: a controlled adaptive-worm proof of concept exists, agentic tools have been observed in real attacks, and one reported APT malware campaign used model-generated commands during execution. These sources do not verify a deployed, continuously self-rewriting malware system that repeatedly changed its code while retaining function.

## Further runtime-AI cases reviewed

| Case | Evidence | What remains unproven |
| --- | --- | --- |
| LAMEHUG / PROMPTSTEAL, 2025 | [CERT-UA](https://csirt.csi.cip.gov.ua/en/posts/apt28-targets-security-and-defence-sector-with-ai-powered-software) identified a phishing campaign against Ukraine's security and defence sector and describes the malware's LLM-based command generation. [GTIG](https://cloud.google.com/blog/topics/threat-intelligence/threat-actor-usage-of-ai-tools) reports APT28 use in live operations and model-generated commands for collection tasks. | The reported objectives were fixed collection tasks. The reports do not show repeated code rewriting, independent target selection by the implant, or a measured count of successful model calls per victim. CERT-UA's APT28 attribution is moderate confidence. |
| QUIETVAULT, 2025 | [GTIG](https://cloud.google.com/blog/topics/threat-intelligence/threat-actor-usage-of-ai-tools) lists the stealer as observed in operations and describes its use of AI prompts and installed AI command-line tools to search for additional secrets. | GTIG gives less case detail than for LAMEHUG: the public report does not quantify completed model calls, infections, or changes to the stealer's code. This is a separate operational runtime-AI design, not evidence of self-rewriting. |
| PromptSpy, February 2026 sample | [ESET](https://www.welivesecurity.com/en/eset-research/promptspy-ushers-in-era-android-threats-using-genai/) observed a model-guided, multistep Android interface interaction in its analysis. [GTIG's later examination](https://cloud.google.com/blog/topics/threat-intelligence/ai-vulnerability-exploitation-initial-access) confirmed an agent-like module and inferred that the design could support more interface goals. | ESET had not seen PromptSpy in its production telemetry; a possible distribution site is weaker evidence than a confirmed infection. Neither report shows self-modification. GTIG's broader-goal assessment is an inference from code. |
| NIK C2, October 2026 | [Talos](https://blog.talosintelligence.com/nik-c2-new-ai-enabled-framework/) found an active framework server and analyzed an implant with an actor-requested model API feature. It assessed the framework as more than a proof of concept with moderate confidence. | The model feature is operator-directed. The report does not establish that the model changed the implant's behavior autonomously or that a particular victim completed a model call. |
| VOLTA, October 2026 sample | [Talos](https://blog.talosintelligence.com/appraisal-by-ai-model-driven-victim-prioritization-in-the-volta-infostealer/) analyzed a sample first seen October 11 with an optional model-based assessment of collected victim data and alternate models if a request is refused. | The report does not provide a victim count or trace of a completed model request in a field infection. Its AI role is post-collection analysis, not code revision. |
| 3AM ransomware intrusion, September 2026 | [Bitdefender](https://www.bitdefender.com/en-us/blog/businessinsights/3am-ransomware-hybrid-ai-attack) documented a UK school intrusion with rapid, similarly spaced command retries and revisions. It assesses a human-directed, AI-assisted loop as a plausible explanation for the attacker workflow. | Bitdefender could not observe the attacker-side machine, model, or automation. It says a person copying outputs to a model cannot be excluded and calls the hybrid reading a working model, not an established finding. The report does not describe a self-modifying implant. |

LAMEHUG is the strongest operational runtime-model case in this set. PromptSpy demonstrates context-aware actions in sample analysis. NIK C2 and VOLTA show other ways a model can be embedded in malicious tooling, while leaving execution and autonomy questions open. The 3AM incident shows why suggestive retry patterns should remain a labeled inference when model telemetry is missing.

The [four-case runtime-AI evidence audit](runtime-ai-evidence-audit.md) separates resemblance to a self-changing design from evidence that the model behavior ran.

## Revisions to the earlier cases

**APT29 July 2023.** [Mandiant](https://cloud.google.com/blog/topics/threat-intelligence/apt29-evolving-diplomatic-phishing) and [EclecticIQ](https://blog.eclecticiq.com/german-embassy-lure-likely-part-of-campaign-against-nato-aligned-ministries-of-foreign-affairs) list the same malicious German-embassy PDF (`fc53c75289309ffb7f65a3513e7519eb`) and later binary (`0be11b4f34ede748892ea49e473d82db`) by MD5. This directly links the examined artifacts and corroborates the PDF delivery chain and Zulip use. Mandiant names the binary ICEBEAT; EclecticIQ calls that binary a Duke variant. Their naming differs, but the digest shows that they examined the same file. The reports do not independently confirm Mandiant's exact six-downloader count or March ROOTSAW guardrail shift.

**DynoWiper December 2025.** [ESET's detailed report](https://www.welivesecurity.com/en/eset-research/dynowiper-update-technical-analysis-attribution/) reconstructs three deployments on December 29, with revised builds after earlier attempts failed. [CERT Polska](https://cert.pl/en/uploads/docs/CERT_Polska_Energy_Sector_Incident_Report_2025.pdf) analyzes four files across sites as two functional versions and confirms a later attempt after EDR blocking. CERT Polska cautions that executable compilation timestamps can be forged. The reports support a same-day revision sequence, without showing AI involvement in producing it.

The attribution remains unsettled. ESET assigns medium confidence to Sandworm for the **data-wiping component**, cites behavior and code similarities, and says it could not assess initial access. CERT Polska finds overlap with Static Tundra infrastructure and cannot conclusively establish Sandworm participation. The two findings can describe different parts of a multi-stage incident; neither report proves such a division occurred. [ESET attribution discussion](https://www.welivesecurity.com/en/eset-research/dynowiper-update-technical-analysis-attribution/); [CERT Polska attribution discussion](https://cert.pl/en/uploads/docs/CERT_Polska_Energy_Sector_Incident_Report_2025.pdf).

## Next evidence to seek

1. A second original analysis of the exact March 2023 ROOTSAW variants and Mandiant's six-downloader count.
2. Direct evidence linking DynoWiper's build revision to a developer, automation system, or model, if such evidence becomes public.
3. An incident report showing repeated, functional code changes made by a running deployed implant, with a trace that distinguishes model output from operator commands.
4. Broader telemetry on AI-integrated samples with a clear distinction between live deployment, sandbox submission, and branding alone.
