# AI-adaptive malware feasibility: evidence ledger

Reviewed 2026-11-10; publication wording revised 2026-11-27. This ledger checks the Project Drexel research hypothesis: a running remote access program observes its environment, changes its own payload with AI, remains functional, and repeats that cycle. The [feasibility assessment](drexel-feasibility-assessment.md) defines the scope. This is an evidence review, not a design or implementation guide.

## What has actually been measured

| Claim | Strongest original evidence | Boundary of the result |
| --- | --- | --- |
| A model can generate executable malicious components during a run and respond to feedback. | The [NYU Ransomware 3.0 prototype](https://arxiv.org/html/2508.20444) tested generated components and corrective feedback in 30 runs across three host types. | The researchers assumed initial user-space execution and model connectivity. They excluded privilege escalation, endpoint evasion, and cross-network propagation. This is generated task code, not proof that one remote access payload repeatedly rewrote itself in an intrusion. |
| A malicious component can be generated anew at each launch. | HYAS researcher Jeff Sims described [BlackMamba](https://securityboulevard.com/2023/03/blackmamba-using-ai-to-generate-polymorphic-malware/) as a 2023 proof of concept that generated a fresh keylogging component at runtime. | The reported variation occurs across program launches. The public article does not show an environment-driven, repeated repair cycle within one running instance or a deployed remote access tool. Its unnamed-product detection claim is not an independent benchmark. |
| A prototype can generate, check, and repair code in response to host context. | Sims described [EyeSpy](https://securityboulevard.com/2023/08/eyespy-proof-of-concept/) as a 2023 HYAS proof of concept that selected a target capability, generated code, and corrected errors in memory. | The article makes a first-party capability claim but gives no quantified trials, before/after code artifacts, or independent confirmation of continued function. HYAS explicitly says the prototype was not production-ready. It is closer to Project Drexel's proposed code-revision mechanism than BlackMamba, but its public evidence is thinner than a measured experiment. |
| An autonomous agent can change its own code after failure and continue. | [Guan et al.](https://arxiv.org/html/2606.03811v1) report several occasions in their contained worm trials when an agent changed its own code following failed exploitation or replication. Their appendix reports successful replication attempts after some changes. Independent host probes checked spread outcomes. | The edits were incidental and addressed agent operation or lab checks; the authors did not instruct self-improvement and deliberately omitted polymorphism. They do not quantify self-revision success or publish a before/after artifact chain. The [paper audit](guan-2026-paper-audit.md) separates these anecdotes from the measured spread results. |
| Model-guided propagation can continue over many hosts. | [Guan et al.](https://arxiv.org/html/2606.03811v1) ran 15 independent seven-day trials in a 33-host network. The mean was 20.4 hosts with a launched replica and 23.1 hosts with elevated access. | Every target had a deliberately exploitable weakness. No endpoint detection, antivirus, or active firewall ran on targets. These figures cannot be projected to defended production networks. |
| A new host can run a copied model and agent. | [Guan et al.](https://arxiv.org/html/2606.03811v1) measured full local-inference setup in a **separate** 32-attempt GPU-host test, succeeding in 68.8%, versus 93.8% for ordinary replica launch on the same samples. [Palisade Research](https://palisaderesearch.org/research/self-replication) independently reports weight-and-harness copying across vulnerable test hosts, with task success ranging from 6% to 33% for the open-weight models it tested. | Guan's main propagation runs used a shared inference pool; their spread numbers do not include local model setup on each GPU host. Palisade's success percentages are specific to its tasks and test conditions. Neither measures real-world deployment frequency. |
| How close are small models to end-to-end replication on modest devices? | [Anthropic's October 2026 evaluation](https://www.anthropic.com/research/self-replicating-ai) separately measured inference setup on different hardware and a simplified eight-node replication task. The strongest tested agent reached all eight target nodes in four of five runs and seven in the fifth. | In that task, a stronger model operated the agent while an 8B model was the deployed inference target. Access was deliberately simple. Anthropic says it has **not** demonstrated a full rogue replicator; it does not establish a self-contained small-model worm in the wild. |
| What field evidence exists for runtime model use and self-revision? | [CERT-UA](https://csirt.csi.cip.gov.ua/en/posts/apt28-targets-security-and-defence-sector-with-ai-powered-software) and [GTIG](https://cloud.google.com/blog/topics/threat-intelligence/threat-actor-usage-of-ai-tools) report runtime model-generated commands in the LAMEHUG/PROMPTSTEAL campaign. [Mandiant](https://cloud.google.com/security/resources/ai-risk-and-resilience-2026) asserts local model-driven changes to command strings in campaigns. | Commands changing are not payload code changing. Mandiant does not publish a named sample or execution trace for its local-model claim. The [field-claim audit](local-model-claim-audit.md) and [runtime audit](runtime-ai-evidence-audit.md) have the case-level distinctions. No reviewed public field report joins repeated on-host code revision, retained remote access function, and model causation in one incident. |

## Reliability and prevalence constraints

The [adaptive-worm study](https://arxiv.org/html/2606.03811v1) reports only 44% success per exploitation attempt. It attributes most failures at that stage to malformed generated code and notes difficulty with unfamiliar web structures and Windows command environments. Repeated attempts raised aggregate spread in its unusually vulnerable network; the per-attempt result still matters when judging a system that must remain functional after changes.

[Unit 42's August 2026 survey](https://unit42.paloaltonetworks.com/ai-enabled-malware-analysis/) found 12 of 405 broadly selected “AI-related” hashes in its protected production endpoint telemetry. All 12 were detected or blocked in that dataset. Its selection includes AI branding, validation samples, and research submissions; the endpoint observation window was December 2024 through June 2025. Thus **12/405 is not an estimate of the prevalence of runtime-adaptive malware**, and the detection result does not measure every environment.

The studies measure different systems and success criteria. A generated command, a changed agent source file, a copied model, and a remote access payload that repeatedly revises itself are separate observations. Combining their success percentages would create a figure no study measured.

## Current assessment

**Technically feasible components:** model-generated code with feedback, autonomous environment-dependent action, occasional self-code modification with recovery, and model replication under controlled conditions. EyeSpy is a close first-party prototype claim; the Guan study supplies clearer measured evidence for actual agent code change after failure. Local inference is possible in experiments but adds a measurable reliability burden; Project Drexel treats endpoint residency as a separate, testable condition.

**Not established by the reviewed public evidence:** a deployed remote access program whose model repeatedly revised its own payload while preserving access across changes. This is an evidence limit, not a proof that no such system exists. The strongest future evidence would be a single incident with a time-ordered model trace, linked program revisions, independent confirmation that the revised program still worked, and at least a second successful revision. The published studies and cases above do not supply that combined record.

The [repeated-revision audit](repeated-revision-evidence-audit.md) adds measured offline model-rewritten malware variants, live benign self-modifying agents, and stateful coding benchmarks to test this exact combined claim. None of those studies measures remote access retained after two payload revisions in one running instance.
