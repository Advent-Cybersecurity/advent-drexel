# Unit 42 agentic campaigns: script variants and persistent web shells

26 November 2026. Source-only audit of Unit 42's 24 November first-party [*Recent Trends and Tactics of Agentic AI Attacks*](https://unit42.paloaltonetworks.com/autonomous-ai-agent-threat-campaigns/). The report covers **more than ten selected campaigns observed July–September 2026**. Its published examples are illustrative; the article does not release a complete per-campaign trace, prompts, process lineage, or all candidate artifacts. No payload was obtained or executed for this audit.

The strongest Drexel-adjacent observations have different units:

| Observation in report | What it establishes | Boundary for the strict claim |
| --- | --- | --- |
| An agent pivoted from a Linux PHP web shell to a Windows IIS server, then placed ASPX web shells at more than 40 paths in 26 minutes, rotating among five variants (§ Multi-OS Compromise). | Rapid delivery of multiple **web-shell artifacts** across locations. | The five variants are not shown as successive executable revisions accepted within one identified continuing process. The report does not give a command/result after each variant. |
| One session contained 40–100 distinct Base64-encoded delivered payloads (§ Dynamic Command Encoding). | Many one-use, target-specific scripts. | A distinct encoded payload is neither a retained version nor a successful remote-control check. The report does not provide a complete version lineage for any one implant. |
| An earlier port-sweep script was followed 21 seconds later by a tailored second script (§ Adaptive and Strategic Attacks). | Fast feedback-driven **task selection and script creation**. | The scripts do different reconnaissance tasks; the second is not established as a code revision of the first. |
| Cortex XDR process-chain view shows Python, PHP, and Bash script executions (Figure 9 and § Absence of Custom Tools and Malware). | Several script languages were launched in the **same process chain**. | A process chain includes child processes and is not proof that a single PID retained and activated multiple versions. |
| Analysts recovered two WMI-backdoor versions, with Chinese comments and a later English-only comment version (§ Operator Fingerprints). | Two artifact versions can be compared. | The described difference is comment language, not a demonstrated functional code change. Model-output provenance, active process identity, timing of adoption, and after-each command results are absent. |

The authors say they recovered hundreds of unique scripts but **no compiled backdoor, custom C2 framework, DLL implant, or shellcode loader** in these campaigns (§ Absence of Custom Tools and Malware). They describe web shells as a persistent foothold. This is a substantive contrast to a resident, self-revising RAT: the controller may repeatedly send new standalone commands through a stable web shell while the shell itself never changes. The report documents process volume and some named XDR detections, but it has no total attempted-action denominator or per-event detection timing for Drexel. Its reported inter-command medians (23.9 seconds in a human phase, 1.4 in an agent phase) come from a **subset**; they are not a model inference latency or a deployment cost.

**Assessment:** strong field evidence of rapid agent-directed script generation and artifact churn after foothold, weak evidence for attribution to an exact model in individual examples, and no evidence of two model-caused active revisions in one continuing remote-access process. The feasibility paper should use this case to explain why *many variants, a shared process chain, and persistent access* do not jointly establish Drexel's tighter serial-revision outcome.
