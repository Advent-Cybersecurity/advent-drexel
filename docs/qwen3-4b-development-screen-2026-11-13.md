# Qwen3-4B development screen and simple size control

**Status, 2026-11-13:** Public development screen. These 16 reused questions are not sealed or structurally independent. The result identifies a workable reference for a later study. A separate warm CPU pilot found a setting-dependent resource tradeoff, but these questions do not establish retained broad capability or a new compression method.

## Artifacts and procedure

The reference is the third-party [Bartowski Qwen3-4B-Instruct-2507 Q4_K_M GGUF](https://huggingface.co/bartowski/Qwen_Qwen3-4B-Instruct-2507-GGUF/tree/ae44f08e1392f39c0e474af10c3ff8355c8b6688) from pinned repository revision `ae44f08e1392f39c0e474af10c3ff8355c8b6688`. Its locally checked file size is **2,497,280,736 bytes** and SHA-256 is `2fde00ce69dd4899c70d020845e2638353015bba0fdf161b3eb965f2bca4464e`. The [official Qwen config](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/blob/1b4199c4f36b0cef378bfb12390c18780c18af4c/config.json) reports 36 layers, 2,560 hidden channels, 9,728 FFN channels, and tied input/output embeddings. This community file is a screening reference, not a fresh export from pinned official source weights.

The fixed public development manifest is [`generated-quality-dev-v4-2026-11-12.json`](../data/generated-quality-dev-v4-2026-11-12.json), SHA-256 `55bd65706fc9a907f7e469cf2a675ba62e5474d44f3a810a23c69ef94de1c44b`. It contains eight inventory arithmetic and eight ordered reading-room state questions, drawn from four reused templates per family. The `reasoned_512` prompt requests explicit intermediate quantities and a final answer. The [runner](../scripts/run_generated_multistep_quality.py) fixes temperature zero and a 512-token completion limit. The primary scorer reads the last numeric token only after a normal stop; final-line format compliance is secondary. The scorer cannot infer whether a correct number arose from a reliable chain of steps.

Both model releases were served separately on the same CPU with pinned `llama.cpp` b12283: four threads, four batch threads, context 2,048, batch 512, one parallel slot, and `--no-repack`. The server listened on loopback. The raw [Q4_K_M responses](../data/generated-quality-dev-qwen3-4b-reference-2026-11-13.jsonl) have SHA-256 `a07610fbf3c8a11e1c76f951f4e8885742b7c11ce81d61b784f068f5bb989284`; its [server log](../data/generated-quality-qwen3-4b-reference-server-2026-11-13.log) records the load and request settings. The raw [Q4_K_S responses](../data/generated-quality-dev-qwen3-4b-q4ks-control-2026-11-13.jsonl) have SHA-256 `66098364b749fd17024654d9dda6882ad8370e0c80e815cc81665cb6bd2638a4`, with a separate [server log](../data/generated-quality-qwen3-4b-q4ks-control-server-2026-11-13.log). The response files record finish reasons, usage, server timings, wall time, and the model path reported by the server. Model-path equality is not cryptographic attestation of the weights resident in the server process.

## Results and decision

| Public development result | Arithmetic correct | Ordered state correct | Normal stops | Final-line format |
| --- | ---: | ---: | ---: | ---: |
| Q4_K_M reference | 8/8 | 8/8 | 16/16 | 7/8 in each family |
| Q4_K_S simple control | 8/8 | 8/8 | 16/16 | 8/8 in each family |

The 4B Q4_K_M reference clears the previously declared **60% development point-rate floor in each family**. The earlier 1.5B reference on this same v4 manifest scored 5/8 arithmetic and 3/8 state, so it did not clear that screen. The two files are different models and conversion lineages; those rates are not a controlled model-scale ablation. Even 8/8 on eight questions gives little precision about future questions, and the repeated templates cannot show transfer to unseen dependency structures. No evaluation manifest has been frozen and no candidate has been scored on sealed cases.

The same repository revision also supplies a Q4_K_S release, locally checked at **2,383,309,536 bytes**, SHA-256 `952af947c6aabf7b72f7d8e279e76f7bf4b0d12431eb3abb588ef312865622d8`. Its complete GGUF is **113,971,200 bytes (4.56%) smaller** than Q4_K_M. It matched the reference's 16/16 correctness on these public development items, with better final-line compliance. Eight successes per family are too few and too correlated to show noninferiority. It is the simple whole-format control for subsequent method comparisons. The two community releases have the same source model name and repository revision, but their upstream quantization details are not a substitute for a controlled, same-source original-checkpoint export.

## Next falsifiable step

The [simple-control resource pilot](qwen3-4b-q4ks-resource-pilot-2026-11-13.md) found lower CPU time in five warm pairs under each repack setting, but opposite process-RAM directions; neither cold attempt admitted a pair. For a decisive study, export a Q4_K_M reference and candidate from one pinned official BF16 source, freeze disjoint dependency structures and a format-blind scorer, and compare complete package bytes, cold process and cgroup peak RAM, and full-request CPU-seconds. A custom physical-pruning method must also beat same-width ordinary pruning and a near-byte simple quantization control. The companion [physical-width hypothesis](composition-conditioned-aligned-pruning-hypothesis-2026-11-13.md) and [CPU tensor audit](frontier-cpu-static-topology-audit-2026-11-13.md) define the mechanical tests and limits.
