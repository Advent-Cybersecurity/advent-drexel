# Environmental observation integrity in Project Drexel

Advent Cybersecurity source-only review, 27 November 2026 (America/New_York). No model, agent, malware, payload, or defensive product was run. This note examines a feasibility condition in the [version 0.4 preprint](../paper/drexel-feasibility-v0.4.tex): before a local model can adapt usefully to an environment, it must receive decision-relevant observations with known provenance, freshness, and completeness. The note proposes only a future **benign, isolated** evaluation.

## Question and boundary

The preprint's RQ1 requires a time-stamped environmental observation, a model-conditioned decision, a resulting change in invoked behavior, and independently checked retained function. Its RQ3 additionally requires exact model-to-code provenance, two active executable revisions in one continuing process, and function after each. RQ4 separates raw telemetry, alerts, enforcement, and function. None of those outcomes follows merely from the model having read a diagnostic string.

Let `E_t` be the experimenter-assigned environment at time `t`; `O_t` the observations delivered to the agent; `D_t` its decision; `V_t` the accepted active version, if any; and `F_t` the independent benign task result. A separate recorder holds `G_t`, an independent measurement of the actual environment state, and `H_t`, the defender events and collection-health record. A full causal record would connect `E_t -> O_t -> D_t -> V_t -> F_t` while retaining `G_t` and `H_t` outside the candidate's editable success path. This notation is a proposed measurement model, not an observed Drexel trace. `O_t` may be correct, stale, incomplete, erroneous, or contain instructions that were never part of the trusted task. A useful adaptation claim needs both evidence that the input caused the decision and evidence that the input represented the relevant environment accurately enough for the task. Those are different questions.

The present trust-boundary review adds **environment sensing and decision validity** to the existing [feedback-integrity audit](feedback-integrity-audit-2026-11-26.md), which addresses poisoned *evaluation feedback during offline self-improvement*. It also differs from the [tool-update audit](tool-update-adoption-boundary-2026-11-26.md), which concerns previously trusted *tool implementations changing outside the model's context*. Either issue could coexist with corrupted environment observations, but its published outcome is not a measurement of this new construct.

The two 2026 benchmark papers add a useful distinction absent from a simple prompt-injection account: even without an adversary, an incomplete or incorrect tool response can change an agent's outcome, while a flawed evaluation fixture can confound attribution of the resulting score. Conversely, a model may produce a plausible response to false input and still fail the independently verified task. These are **inferences for the proposed Drexel study**, not measured outcomes of that study.

## Threat model for a benign analogue

**System and asset.** A consented client-server application performs a harmless deterministic task. A local model may propose a bounded change in benign functionality after reading diagnostic observations. The assets are correct task behavior, accurate provenance of any accepted code revision, and the integrity of the research record. The application has no exploitation, persistence, exfiltration, or evasion objective.

**Trust boundaries.** The researcher-set task, environment assignment, independent task oracle, and raw experiment ledger are trusted for the study's purpose. Observations delivered to the model—diagnostic text, tool responses, repository or configuration content, and prior agent-generated summaries—are *data* whose origin and fidelity must be measured. They should not acquire authority to redefine the task. A post-change test result is a separate feedback channel; it is not proof of every retained property or of the environment's true state. Defender-product telemetry is yet another observation channel whose configuration and capture health need independent records.

**Permitted perturbations in a future study.** A study could compare clean, withheld, delayed, incomplete, inconsistent, and instruction-bearing **synthetic** observations. It would not need a live malicious sample or an operational prompt-injection payload. The evaluator would change at most the declared lower-trust observation fixture, not the trusted task, model weights, independent oracle, or ground-truth environment. Each perturbation class and timing would be preregistered. This delimitation makes it possible to attribute a wrong decision to observation quality rather than silently changing the task itself.

**Failure classes.** (1) The model follows an instruction embedded in low-trust data instead of treating that text as evidence; AgentDojo supports the general agent concern. (2) The model acts on a missing, wrong, or stale diagnostic value; AgentNoiseBench supports sensitivity to incomplete and erroneous tool outputs, while *staleness in Drexel's environment* remains a specific untested hypothesis. (3) A revision is promoted because the feedback or test fixture is contaminated; the prior Roesner–Kohno audit addresses this distinct path. (4) A study labels absent sensor events as stealth even though the event type was not enabled or collection failed; Sysmon documentation shows why configuration and health are material. An authenticated signature or trusted log can bind an observation to a source; a hash alone detects alteration only against a trusted reference. Neither proves that the measurement was true or current.

## Consequences for the four research questions

- **RQ1, environmental adaptation.** Record the actual constraint and the model-visible observation separately. A decision that changes after a synthetic observation change demonstrates input sensitivity; it does not establish *correct* adaptation unless the relevant ground truth and post-decision benign function agree. A fixed-rule controller and an unchanged continuation should face the same fixture. Wrong or missing inputs should be reported by type, not pooled into a universal environment success rate.
- **RQ2, local model.** The ability to detect uncertainty or request a permitted recheck is part of task quality and resource cost. A model that retries until it receives a clean observation consumes time and energy; a single successful call does not capture complete-task cost. No cited source measures that tradeoff for Drexel's local model and hardware combination.
- **RQ3, serial continuity.** The model's diagnosis, decision, response, accepted artifact, activation evidence, and after-each external task must remain linked. A self-reported successful update or a model-generated test cannot replace the external oracle. The two revision stages should retain the exact observation each saw, so an incorrect second decision is not misclassified as an update-mechanism failure.
- **RQ4, defender outcomes.** Preserve the named sensor, version, enabled policy, event filters, clock alignment, collection window, and health/error indications. Report a missing event as *unknown* when collection is not known to have covered it. Raw events, named alerts, enforcement, and application-side function remain separate fields. An unavailable or incomplete log cannot establish invisibility.

## Falsifiable questions for later authorized research

1. Under a declared benign environment change, does the model's recorded decision differ from its decision under the matched baseline observation, and does the independent task oracle confirm a useful difference? This separates response to data from mere compatibility across hosts.
2. Holding the true environment constant, how often do incomplete, inconsistent, or delayed observations change the decision or task outcome relative to clean observations? Report each perturbation and error class separately, including abstention and permitted verification actions.
3. Can a typed, provenance-labeled observation interface reduce wrong changes or unauthorized instruction following without losing benign task function? Compare against the same model, budget, and tasks using an unrestricted diagnostic text interface. CaMeL motivates the control/data separation; its AgentDojo numbers do not predict this result.
4. Do the independent oracle and raw ledger detect disagreements between the agent's claimed success and the actual activated version or function? Audit the evaluation fixture itself, following AgentSuite's user/environment/ground-truth/evaluation separation.
5. When telemetry is absent, can the study determine whether the event was unobservable under the enabled sensor configuration, filtered, delayed, lost, or truly not emitted? If not, classify that trial's telemetry field as unresolved rather than negative.

Before any such experiment, freeze the model and runtime versions, environment matrix, observation fixtures, permitted verification steps, task oracles, budgets, and decision rules. Preserve all eligible attempts, rejected proposals, time stamps, raw observations, accepted artifact hashes, and reasons for censoring or missing data. Use an isolated harmless application and preregister the thresholds; this review supplies neither a sample-size estimate nor a result.

## Current conclusion

Existing primary studies establish that tool-returned instructions, noisy tool results, poisoned feedback, and benchmark defects can affect agent behavior or its evaluation in their own settings. Sysmon documentation establishes that defensive telemetry depends on configuration and collection health. Together these sources justify treating the integrity of environmental observations as a **cross-cutting validity condition** for Project Drexel's existing research questions. They do **not** demonstrate that an endpoint-local model can correctly adapt across declared host strata, make two active code revisions in one process, or evade a named defender. The immediate contribution is a sharper causal record and a source-grounded benign protocol; empirical rates remain unknown.
